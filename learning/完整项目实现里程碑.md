# 完整项目实现里程碑

## 目标与执行方式

本文件承接首轮 62 个学习单元（A：Boot 10 个；B：Cloud 10 个；C：项目模块 42 个），作为 D 阶段完整实现与交付验收。目标是用户亲手完成完整项目，覆盖功能、前后端联调和部署运行，并能解释与独立修改代码。进度按验收推进，不按固定天数宣布毕业。

每个里程碑开始前：核对对应参考源码，列出全部功能入口及分支；确认自己项目现状；按每天约 4 小时拆成后续 Day 63、64……或尚未完成单元的补课，并将具体日期、教案和验证记录写入每日进度。不要在未看代码时预写虚构的完整教案。

下表为模块覆盖初稿，尚不是经过全面源码审计的功能清单。发现遗漏必须补入。A/B/C 阶段已有实现应继续完善，不重复推倒重写。

## 前置验收

进入项目模块前先通过 Boot 持久化 API 与 Cloud 两服务＋网关验收，详见每日课程计划。已有注册发现、调用与网关实验需要继续完善成业务实现，不能仅凭演示成功就认定 M01 全部完成。前端与中间件基础在首次使用前安排补课；未验证的依赖兼容性必须保留为待办。

## 最终完成条件

1. 源码核实后的功能映射无未说明的缺项；差异和范围调整明确记录并与用户确认。
2. 自己的工程具备可运行的完整业务实现，核心页面和接口形成端到端闭环；参考工程不能替代自己的功能。
3. 构建、初始化、启动步骤可复现，相关正常、边界与失败场景有实际验收记录。
4. 用户能够说明主要模块的原理、数据流、权限边界与设计取舍，并能定位故障。
5. 用户能够独立完成变化需求；教案完成或代码照写成功不等于掌握。
