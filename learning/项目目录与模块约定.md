## 补强阶段：独立课独立模块，有依赖才持续演进

没有真实代码或运行时依赖的课程，在仓库下新建 `day-NN-英文主题/`，拥有独立 POM、src、配置和运行说明。IDEA 可以分别导入各目录的 POM；IDEA 的模块概念不意味着必须在仓库根目录创建聚合 POM。

知识上的前后关系，不等于 Maven 模块依赖。例如 Day 02 需要知道 Day 01 的启动方法，但它仍然是独立练习，不能通过依赖 Day 01 的应用 JAR 来省略脚手架。允许把自己已理解的最小骨架作为当天起点，但必须在教案中列清完整基线、文件和改动，让当天模块能够单独构建。

| 单元 | 目标目录 | 模块边界 |
|---|---|---|
| 01 | `day-01-spring-boot-hello/` | 独立 Maven/hello 应用 |
| 02 | `day-02-spring-di/` | 独立依赖注入练习 |
| 03 | `day-03-boot-auto-config/` | 独立自动配置练习 |
| 04 | `day-04-spring-mvc/` | 独立 HTTP 参数与路由练习 |
| 05 | `day-05-config-logging/` | 独立配置与日志练习 |
| 06 | `day-06-mybatis-crud/` | 独立持久化练习，使用学习数据 |
| 07 | `day-07-validation-errors/` | 独立校验与异常练习 |
| 08 | `day-08-transactions/` | 独立事务实验，自带两次写入所需代码 |
| 09 | `day-09-pagination/` | 独立分页与验证练习 |
| 10 | `day-10-boot-assessment/` | 独立综合验收应用，重建必要能力，不依赖前面应用 JAR |
| 11–20 | `day-11-cloud-lab/` | 用户/文档/网关组成同一实验；按日新增能力并记录真实依赖 |

Cloud 实验确有调用链依赖：Day 11 建 user-service/document-service，Day 12–14 继续完成注册发现、远程调用和多实例；Day 15 新增 gateway-service，Day 16–20 在同一实验中完成过滤器、配置和故障验收。两个用户服务实例使用同一模块的不同端口，不为每个实例复制模块。

以后若某节 Cloud 课实际可以独立学习，也应按日新建模块；如果调整复用边界，必须先在教案说明依赖关系与复用理由。连续实验每课写明当天变更、运行前置及验收，不把旧练习的变化算作新模块自动完成。

## 正式项目阶段：前后端两个顶层工程

从 Day 21 开始，自己的正式实现落在 `knowledge-base-backend/` 和 `knowledge-base-frontend/`，不再为每一天创建正式业务工程。按课程逐步创建需要的服务模块和前端页面，不提前生成全部空壳。

学习成果可以迁入正式工程，但需明确迁入哪些自己写过的文件、调整哪些配置、为何符合正式业务需求。正式工程不能通过编译依赖或运行前置依赖 `day-*` 练习模块；Cloud 实验保持可独立复习。实际服务依赖在后端内部表达，前后端通过 API 协作。

参考工程位于 `/Users/hingfaattam/projects/learn_projects/enterprise-knowledge-base`，它与自己的工程目录名称相似，所有教案必须注明“参考”还是“自己的实现”，不能编辑错目录。

## 每份教案的必填信息

1. 仓库绝对路径、当天模块名、模块绝对路径、当前目录树与目标目录树。
2. 本课是新建独立模块还是继续现有实验；若复用，列明真实依赖与理由。
3. 在“文件位置（复用/新增/修改）”内列全文件路径，区分仓库根和模块根。
4. POM 的 artifactId、应用名、目标 JAR 名称与命令目录一致。
5. 构建/运行命令明确工作目录。不能让用户在无 POM 的仓库根执行 Maven。
6. 本课代码由用户亲手创建。文档里的规划目录不视为已经存在或可运行。
