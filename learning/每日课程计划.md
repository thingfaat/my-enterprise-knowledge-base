# 企业智能知识库：从源码学习到完整实现

## 使用说明

本计划根据本地项目的模块与源码入口初步编排，不是知识星球原课程目录的复刻。学习者会 Java，Spring Boot 尚不熟悉，每天可投入 4 小时；SQL 熟练度待学习中确认。以 Java 后端为主，前端用于理解完整交互。当前只完成目录、依赖声明及部分文档检查，尚未逐条核实业务实现，也未进行运行验证；表中的主题和验收是待验证的学习目标，不代表功能已完整实现。

每天 4 小时：回顾 15 分钟 → 原理讲解 45 分钟 → 源码追踪 60 分钟 → 独立练习 90 分钟 → 验收与记录 30 分钟。一天只追一条主要调用链。卡住时记录预期、实际结果、日志与猜测，环境排障可单独增加一天。每个阶段设置复盘与验收单元，按实际掌握情况补课，不强求日历连续。

最终目标：学习者能够理解整体架构和关键设计，亲手写出自己的完整企业智能知识库，覆盖后端业务、前端交互、中间件集成与可复现的启动验收，并能独立处理变化需求。

## 学习阶段与完成边界

首轮安排 62 个学习单元：10 个 Spring Boot 基础单元、10 个 Spring Cloud / Spring Cloud Alibaba 专项单元、42 个项目模块单元。每天约 4 小时；Day 表示课程编号，不是必须在一个自然日内完成的期限。基础与 Cloud 各预留约 7–10 个学习日的初始节奏，按验收结果合并已掌握内容或拆分难点，但不跳过对应交付。

| 顺序 | 单元 | 学习重点 | 自己项目的阶段交付 |
|---|---|---|---|
| A | Day 01–10 | Spring / Spring Boot 基础 | 含配置、数据库、校验、事务和异常处理的最小文档 API |
| B | Day 11–20 | Cloud 专项过渡 | 用户服务＋文档服务＋网关；注册发现、远程调用、负载均衡、配置与故障实验 |
| C | Day 21–62 | 项目源码学习与逐模块实现 | 登录权限、文档、协作、搜索统计、AI/RAG、图谱及前端最小业务闭环 |

### 阶段验收门槛

- A → B：用户能亲手完成一个持久化 API，解释 Controller → Service → Mapper，验证输入错误与事务回滚。未通过就补课，不直接进入多服务开发。
- B → C：用户能独立启动自己的两个服务与网关，完成服务名调用、双实例实验、配置读取/刷新验证和服务停机排障；能解释本地事务与跨服务操作的边界。
- C → D：核对自己的真实功能清单与不足，携带现有代码继续补齐，不能把“读过全部模块”算作完成。
- 最终完成：按里程碑验证功能覆盖、前后端闭环、干净环境启动和独立实现能力；原作者的缺陷不机械照抄，差异明确说明。

正式教学文档必须遵循根目录 `AGENTS.md` 的七段结构。本文是课纲，不能替代经过代码核验的完整课程。每日开始先阅读本计划和 `每日进度.md`，再检查当天实际源码。

### 按需补齐中间件与前端基础

MySQL 在 Day 06 前核对学习环境；Nacos 在 Day 12 前核对现有部署。Redis 在首次用于登录状态或缓存前补充，RabbitMQ 在消息课前补充，MongoDB 在正文存储实现需要时补充，Elasticsearch 在搜索课前补充，Neo4j 在图谱课前补充。每项包含最小实验、数据流与失败排查，增加的补课记录到进度台账。

React、TypeScript、请求封装和路由在首次编写登录页面前安排必要补课；之后随模块完成页面，最终阶段补齐所有交互与状态，不能一直停留在后端接口。

Sentinel、Seata 等内容先核对参考项目是否实际接入，再判断是否需要专项课；中间件目录存在组件不等于项目已使用。超时、重试、幂等和事务边界属于必学概念，不以未接入某个治理组件为由跳过。涉及具体组件接入、版本与配置时，备课需核对实际依赖及对应官方资料，并通过实验验证，不能把依赖声明当作已生效证据。

### A：Spring / Spring Boot 基础（Day 01–10）

在自己的项目中从最小应用开始，演进为简化文档服务。Cloud 阶段继续复用它；练习性的临时代码与后续业务实现明确区分，不复制全部参考工程。

| 天 | 主题与源码入口 | 亲手实现 | 验收标准 |
